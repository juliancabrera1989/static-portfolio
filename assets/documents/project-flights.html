Live Demo: flightmanagement-e4u9.onrender.com Repository: github.com/juliancabrera1989
1. Architecture & Landing Page Overview

The application is architected around Laravel's MVC pattern, employing Eloquent ORM with eager loading optimization to prevent N+1 queries across complex relations (flights, airports, airlines, and gates). The front-end leverages React components for real-time board rendering and map canvas visualizations.

2. Role-Based Access Control (RBAC)

Objective: Validate operational scoping and resource access isolation across user roles (Airline Staff, Airport Staff, and Passenger).

Result: Enforces strict domain integrity by restricting edit/delete permissions dynamically based on the authenticated context.

Role Context 1: Airline Staff Scope (British Airways)

Operations are locked strictly to the assigned carrier. Field-level restrictions disable editing the airline domain.

4. Graph Optimization Algorithm (Dijkstra)

Objective: Compare shortest-path calculation between the same origin/destination under broad vs. constrained time windows.

Result: Demonstrates how temporal restrictions invalidate the mathematically shortest geographic path, forcing the algorithm to recalculate a valid connection.

5. Alternative Routes Enumeration (DFS)

Objective: Enumerate alternative itinerary paths between Origin and Destination using Depth-First Search (DFS) with backtracking.

Result: Restricting visited nodes enforces strict topological uniqueness (preventing redundant airport sequences), while allowing node repeats exposes schedule variations.

Test 1: Search Form (Allow Repeat Nodes: OFF)
Test 2: Search Form (Allow Repeat Nodes: ON)
Result 1: Unique Topologies (Pruned Intermediate Nodes)
Result 2: Discovered Combinations (Schedule Variations Allowed)
6. Backend Performance & Conclusion
By utilizing database indexing on foreign keys (departure_airport_id, departure_time) and database procedures for batch generation, queries for complex graphs execute in under 40ms. The application achieves clean separation of concerns, resilience under heavy data load (+15,000 records), and flexible real-time monitoring capabilities.
